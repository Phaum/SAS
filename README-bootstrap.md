# Миграция на новый сервер одной командой

Сценарий рассчитан на запуск **на новом чистом Debian/Ubuntu сервере**. Старый сервер должен иметь рабочую стандартную установку 3x-UI с SQLite `/etc/x-ui/x-ui.db` и доступ root по SSH.

## Запуск из GitHub

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Phaum/SAS/main/bootstrap-migrate.sh)
```

Скрипт интерактивно запросит:

- IP, SSH-порт и пароль root старого сервера;
- подтверждение SSH fingerprint;
- домены панели и подписок;
- новые пароли 3x-UI и Grafana;
- данные REG.RU API и имена A-записей.

## Последовательность

1. Проверяет старый сервер и снимает согласованную копию `x-ui.db`, кратковременно останавливая только 3x-UI.
2. Проверяет SHA-256 перенесённой базы.
3. Устанавливает зависимости и подготавливает nginx нового сервера.
4. Показывает dry-run изменения DNS REG.RU.
5. После явного подтверждения переключает A-записи на новый IP.
6. Ждёт обновления авторитетных DNS-серверов.
7. Получает сертификат Let's Encrypt и устанавливает 3x-UI, nginx, Grafana, Loki и Alloy.
8. Восстанавливает пользователей и inbound из старой базы, но задаёт новые параметры панели и подписок.
9. Открывает найденные inbound-порты в UFW, если UFW активен.
10. Проверяет службы и оставляет старый сервер включённым.

Если после переключения DNS финальная установка завершается ошибкой, скрипт пытается вернуть обе A-записи на старый IP. Изменения DNS не атомарны, поэтому фактические записи всё равно нужно проверить вручную.

Рабочие файлы и перенесённая база хранятся в `/root/SAS-migration` с закрытыми правами. Пароль старого сервера и пароль REG.RU в файлы не записываются.

Существующие AAAA-записи автоматически не меняются. Если старый IPv6 больше не используется, удалите или обновите его отдельно.

## После миграции

Проверьте панель, подписки и несколько реальных VPN-клиентов. Не выключайте старый сервер до завершения проверки и истечения DNS TTL.
