# REG.RU: смена IPv4 домена

`regru-change-ip.sh` заменяет совпадающие A-записи через REG.API v2. По умолчанию изменения выполняются сразу. Поддержка IPv6 удалена: существующие AAAA-записи остаются без изменений.

## Запуск

```bash
bash regru-change-ip.sh example.com 192.0.2.10 198.51.100.20 --credentials ./regru-credentials.json
```

Укажите реальные домен, старый и новый IPv4. Без дополнительных параметров обрабатываются все A-записи зоны с точным совпадением старого IP, включая поддомены. Для одной записи добавьте `--record vpn`, для самого домена — `--record @`. Первый аргумент — DNS-зона, например `example.com`. Кириллические домены указывайте в Punycode.

Добавьте `--check` для предварительного просмотра без изменения DNS. Если совпадений нет, ничего не создаётся.

## Доступ

В [настройках API REG.RU](https://www.reg.ru/user/account/#/settings/api/) разрешите IP машины запуска и настройте пароль API. DNS-зона должна обслуживаться REG.RU и быть доступна вашему аккаунту.

При запуске через `manage-migration.sh` логин и пароль читаются из `.env`. Для отдельного запуска можно передать `REGRU_USERNAME` и `REGRU_PASSWORD` через окружение либо создать JSON-файл:

```json
{"username":"ВАШ_ЛОГИН","password":"ВАШ_ПАРОЛЬ_API"}
```

```bash
chmod 600 regru-credentials.json
```

Пароли не передаются аргументами команд. Требуются Bash 4+, curl, jq и стандартные Linux-утилиты. При отсутствии curl/jq скрипт установит их через APT с root или `sudo -n`. На других системах установите зависимости самостоятельно. Режим `--check` также может установить локальные зависимости.

## Перенос и восстановление

Снимок зоны `before.json`, план и журнал сохраняются в закрытом подкаталоге `./regru-backups`; другое расположение задаётся через `--backup-dir DIR`.

Сначала добавляется новый адрес, если его ещё нет, затем после проверки удаляется конкретное старое значение. Другие адреса того же имени, AAAA, MX, TXT и прочие записи не меняются. Новый адрес использует TTL, назначенный API/зоной; сохранение индивидуального TTL не гарантируется.

Перед каждой записью и после неё зона перечитывается. Это не атомарная транзакция: не редактируйте DNS одновременно со скриптом. Между добавлением и удалением в DNS могут присутствовать оба адреса, поэтому новый сервер должен быть готов заранее.

При таймауте записи скрипт проверяет фактическое состояние, не повторяя изменение вслепую. Если результат не подтверждён, выполнение останавливается; уже выполненные изменения сохраняются. Повторный запуск исходной команды позволяет продолжить частично выполненный перенос. Автоматического отката всей зоны нет; снимок и журнал предназначены для проверки и ручного восстановления.

Успешное завершение подтверждает записи через API REG.RU. Публикация DNS и обновление кэшей требуют времени согласно TTL. Скрипт не меняет настройки сети, firewall, NS, сертификаты и конфигурацию приложений.

Проверены IPv4, сохранение нетронутых AAAA/других записей, повторный запуск, частичные ошибки и таймауты на имитации API. На реальном аккаунте REG.RU скрипт не запускался.
